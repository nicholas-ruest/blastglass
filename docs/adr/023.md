# ADR-023: Evidence-sealed payload content

**Status:** Accepted for Blastglass 0.1  
**Decision date:** 2026-11-20

## Context

A hash of only identifiers would not prove which scenario, score and stages were approved.

## Decision

Serialize canonical outcome content—ID, service, scenario, score and stage list—then seal it with correlation and previous hash.

## Consequences

The UI can render useful audit history after restart. Schema evolution must preserve old payload parsing or provide a migration reader.

## Verification and reciprocal mapping

The acceptance surface is: blastglass-evidence, service payload, EvidenceCard. The corresponding implementation and failure tests must cite ADR-023; if that path is removed, this decision is reopened rather than preserved as orphaned documentation.
